# ВышКат — спецификация функций для юнит-тестов

Документ описывает контракт каждой публичной функции ядра `vyshkat_core`: что принимает, что возвращает, какие исключения бросает (с точным текстом) и какие граничные случаи нужно покрыть. Под каждым модулем — список тест-кейсов с идентификаторами, по одному `TEST` на строку.

Все утверждения сверены с текущим кодом и проверены прогоном.

## Общие правила

- **Исключения.** Проверять тип через `EXPECT_THROW`, а текст `what()` — там, где он указан в таблице. Тексты — часть контракта: их выводит `ConsoleApp`.
- **Числа с плавающей точкой.** Одиночные значения — `EXPECT_DOUBLE_EQ`, суммы — `EXPECT_NEAR(…, 1e-9)`.
- **Изоляция.** `IntakeService` тестировать с фейком `IInspectionService` (заданный результат + счётчик вызовов), а не только с `ServiceCenter`.
- **Консоль.** `ConsoleApp` тестировать через `std::istringstream` / `std::ostringstream` и поиск подстрок в выводе.
- **Порядок валидации** в конструкторах важен: тест с несколькими ошибками сразу ловит первую по порядку.

Тесты лежат в `tests/` и собираются в цель `vyshkat_tests` (GoogleTest, `ctest`). Имя каждого теста начинается с ID кейса: `EQ01_…`, `AP26_…`.

## 1. `equipment.h` — оборудование

### 1.1. Интерфейсы

| Интерфейс | Метод | Контракт |
|---|---|---|
| `IInventoriable` | `std::string name() const` | Отображаемое имя объекта. |
| | `std::optional<int> inventoryNumber() const` | Пусто, пока объект не на балансе; после присвоения — номер. |
| `IEnergyConsumer` | `double dailyEnergyKwh() const` | Суточный расход, кВт·ч; конечное число ≥ 0. |

Транспорт и вещи, которые потребляют энергию, реализуют оба интерфейса. Проверка — через `dynamic_cast<const IEnergyConsumer *>`.

### 1.2. Виды и `kTitle`

| Класс | База | `kTitle` | `IEnergyConsumer` |
|---|---|---|---|
| `Scooter` | `Vehicle` | `Самокат` | нет |
| `Bicycle` | `Vehicle` | `Велосипед` | нет |
| `ElectricScooter` | `ElectricVehicle` | `Электросамокат` | да |
| `ElectricBicycle` | `ElectricVehicle` | `Электровелосипед` | да |
| `Helmet` | `Item` | `Шлем` | нет |
| `DockStation` | `ElectricItem` | `Док-станция` | да |
| `ChargingCabinet` | `ElectricItem` | `Зарядный шкаф` | да |

`Vehicle`, `ElectricVehicle`, `Item`, `ElectricItem` абстрактны (конструкторы `protected`), конечные виды помечены `final`.

### 1.3. Конструкторы транспорта

`Scooter(nickname, simplicity, wearPercent)`, `Bicycle(…)` — те же три параметра.
`ElectricScooter(nickname, simplicity, wearPercent, dailyEnergyKwh)`, `ElectricBicycle(…)` — плюс расход.

Проверки выполняются **в этом порядке**, первая же неудачная бросает `std::invalid_argument`:

| # | Параметр | Допустимо | Текст ошибки |
|---|---|---|---|
| 1 | вид (`kTitle`) | непустая строка | `Вид транспорта не может быть пустым` |
| 2 | `nickname` | есть хотя бы один символ, кроме ` \t\r\n` | `Кличка не может быть пустой` |
| 3 | `simplicity` | 1…10 включительно | `Простота должна быть от 1 до 10` |
| 4 | `wearPercent` | не NaN | `Износ не может быть NaN` |
| 5 | `wearPercent` | 0…100 включительно (±∞ — вне диапазона) | `Износ должен быть от 0 до 100 процентов` |
| 6 | `dailyEnergyKwh` (только электро) | конечное (не NaN, не ±∞) | `Суточное потребление энергии должно быть конечным числом` |
| 7 | `dailyEnergyKwh` (только электро) | ≥ 0 | `Суточное потребление энергии не может быть отрицательным` |

Кличка хранится как есть, без обрезки пробелов: `Scooter("  Лис  ", …)` даёт имя `Самокат «  Лис  »`.

### 1.4. Методы `Vehicle`

| Метод | Возвращает |
|---|---|
| `name()` | `kindTitle + " «" + nickname + "»"`, например `Самокат «Молния»` |
| `kindTitle()` | `kTitle` конкретного вида |
| `nickname()`, `simplicity()`, `wearPercent()` | значения из конструктора без изменений |
| `dailyEnergyKwh()` (электро) | значение из конструктора |
| `inventoryNumber()` | `std::nullopt` у нового объекта |

### 1.5. Конструкторы вещей

| Класс | Параметры | Проверки |
|---|---|---|
| `Helmet()` | — | нет |
| `DockStation(dailyEnergyKwh)`, `ChargingCabinet(dailyEnergyKwh)` | расход | пункты 6 и 7 из таблицы 1.3 |

Базовая проверка вида у `Item`: `Вид предмета не может быть пустым` (через публичные классы не достижима).

`Item::name()` возвращает только вид: `Шлем`, `Док-станция`, `Зарядный шкаф`.

### 1.6. `assignInventoryNumber(int number)` — у `Vehicle` и у `Item`

1. Если номер уже присвоен — `std::logic_error("Инвентарный номер уже присвоен")`, независимо от `number`.
2. Иначе, если `number <= 0` — `std::invalid_argument("Инвентарный номер должен быть положительным")`; номер остаётся пустым, следующий корректный вызов проходит.
3. Иначе номер сохраняется, `inventoryNumber()` возвращает его.

## 2. `Equipment_factory.h` — фабрики

### 2.1. Типы

| Тип | Поля | По умолчанию |
|---|---|---|
| `VehicleParams` | `name`, `simplicity`, `wear`, `energy` | `""`, `0`, `0.0`, `0.0` |

### 2.2. Встроенные виды (в порядке регистрации)

| Фабрика | `id` | `title` | `needEnergy` | Создаёт |
|---|---|---|---|---|
| `VehicleFactory` | `scooter` | `Самокат` | `false` | `Scooter` |

### 2.3. Методы (одинаковы у обеих фабрик)

| Метод | Контракт |

| `contains(kind) const` | `true`, если вид зарегистрирован. Пустая строка → `false`. |
| `registerType(type, creator)` | Проверки по порядку: пустой `type.id` → `invalid_argument("Идентификатор вида транспорта не может быть пустым")` / `("Идентификатор вида вещи не может быть пустым")`; пустой creator → `invalid_argument("Создатель для вида «<id>» не задан")`; повторный `id` → `invalid_argument("Вид транспорта «<id>» уже зарегистрирован")` / `("Вид вещи «<id>» уже зарегистрирован")`. При ошибке список видов не меняется. Новый вид добавляется в конец. |

## 3. `Fleet.h` — баланс

### 3.1. `std::string formatInventoryNumber(int number)`

Возвращает `"ВК-"` + число, дополненное нулями до 6 знаков: `1 → ВК-000001`, `999999 → ВК-999999`, `1234567 → ВК-1234567` (не обрезается).

### 3.2. `std::string addVehicle(std::unique_ptr<Vehicle>)` / `addItem(std::unique_ptr<Item>)`

1. `nullptr` → `invalid_argument("Нельзя добавить пустой транспорт")` / `("Нельзя добавить пустой предмет")`.
2. Берёт `n = lastNumber_ + 1` — **общий** счётчик для транспорта и вещей, начинается с 1.
3. Вызывает `assignInventoryNumber(n)`. Если у объекта уже есть номер — пробрасывается `logic_error`, объект не добавляется и уничтожается, счётчик **не** увеличивается.
4. Добавляет объект и возвращает `formatInventoryNumber(n)`.

### 3.3. `vehicles() const` / `items() const`

Возвращают `std::vector<const Vehicle *>` / `std::vector<const Item *>` в порядке добавления. `Fleet` остаётся владельцем; указатели остаются валидными после следующих добавлений.

### 3.4. Тест-кейсы

| ID | Сценарий | Ожидание |
|---|---|---|
| FL-01 | `formatInventoryNumber(1)`, `(999999)`, `(1234567)` | `ВК-000001`, `ВК-999999`, `ВК-1234567` |
| FL-02 | новый `Fleet` | `vehicles()` и `items()` пусты |
| FL-03 | транспорт, вещь, транспорт | номера `ВК-000001`, `ВК-000002`, `ВК-000003` — общий счётчик |
| FL-04 | после добавления | `inventoryNumber()` у объекта равен числу из номера |
| FL-05 | `addVehicle(nullptr)`, `addItem(nullptr)` | тексты из 3.2 |
| FL-06 | `nullptr`, затем обычное добавление | номер не потрачен: следующий — `ВК-000001` |
| FL-07 | объект с уже присвоенным номером | `logic_error`; в списке его нет; следующий получает очередной номер без пропуска |
| FL-08 | порядок | `vehicles()` / `items()` в порядке добавления |

## 5. `ServiceCenter_service.h` — `ServiceCenter`

Константы: `kMaxWearPercent = 40.0`, `kMaxDailyEnergyKwh = 2.0`.

`InspectionResult inspect(const Vehicle &vehicle) const`:

1. `wearPercent() > 40` → `{false, "износ <wear> % > 40 %"}`.
2. Иначе, если `vehicle` — `IEnergyConsumer` и `dailyEnergyKwh() > 2` → `{false, "расход <energy> > 2 кВт·ч/сут"}`.
3. Иначе `{true, ""}`.

Сравнения строгие: ровно на лимите — принимается. Числа в причине — кратчайшая запись: `55`, `40.25`, `2.5`.

| ID | Сценарий | Ожидание |
|---|---|---|
| SC-01 | константы | 40 и 2 |
| SC-02 | износ 40 | принят |
| SC-03 | износ 55 | `износ 55 % > 40 %` |
| SC-04 | износ 40.25 | `износ 40.25 % > 40 %` |
| SC-05 | электро, расход 2, износ 10 | принят |
| SC-06 | электро, расход 2.5, износ 10 | `расход 2.5 > 2 кВт·ч/сут` |
| SC-07 | электро, износ 55 и расход 3 | причина про износ (проверяется первым) |
| SC-08 | неэлектрический, износ 0 | принят, `reason` пустой |
| SC-09 | вызов через `const IInspectionService &` | тот же результат |

## 6. `Intake_service.h` — `IntakeService`

`IntakeService(const IInspectionService &inspection, Fleet &fleet)` — хранит ссылки.

`IntakeResult` — `accepted = false`, `inventoryNumber = ""`, `reason = ""` по умолчанию.

### `IntakeResult accept(std::unique_ptr<Vehicle> vehicle)`

1. `nullptr` → `invalid_argument("Нельзя принять пустой транспорт")` **до** вызова `inspect`; `Fleet` не меняется.
2. Вызывает `inspect(*vehicle)` ровно один раз.
3. Отказ → `{false, "", <reason из inspect>}`; `Fleet` не вызывается, номер не тратится, объект уничтожается.
4. Принят → `fleet.addVehicle(…)`, результат `{true, <номер>, <reason из inspect>}`.

### `std::string registerItem(std::unique_ptr<Item> item)`

Без осмотра вызывает `fleet.addItem` и возвращает номер. `nullptr` → исключение из `Fleet` («Нельзя добавить пустой предмет»).

| ID | Сценарий | Ожидание |
|---|---|---|
| IN-01 | фейк «принять», `accept(Scooter)` | `{true, "ВК-000001", ""}`, транспорт в `Fleet` |
| IN-02 | фейк «отказ: причина X» | `{false, "", "X"}`, `Fleet` пуст |
| IN-03 | отказ, затем приём | принятый получает `ВК-000001` — номер не потрачен |
| IN-04 | фейк со счётчиком | `accept` вызывает `inspect` ровно 1 раз |
| IN-05 | `accept(nullptr)` | `invalid_argument`; `inspect` не вызывался; `Fleet` пуст |
| IN-06 | `accept(nullptr)`, затем `registerItem` | вещь получает `ВК-000001` |
| IN-07 | `registerItem(Helmet)` | номер; `inspect` не вызывался |
| IN-08 | `registerItem(nullptr)` | `invalid_argument` «Нельзя добавить пустой предмет» |
| IN-09 | фейк «принять с причиной Y» | `reason == "Y"` пробрасывается |
| IN-10 | с настоящим `ServiceCenter`: износ 55, затем расход 2.5 | оба отклонены с текстами из раздела 5 |
| IN-11 | `IntakeResult{}` | `accepted == false`, номер и причина пусты |

### 9.2. `ConsoleApp(const VehicleFactory &, const ItemFactory &, IntakeService &, const FleetReports &, std::istream &, std::ostream &)` и `run()`

**Цикл.** Перед каждой командой выводится меню:

```text
1 — виды транспорта
2 — принять транспорт
3 — поставить вещь на баланс
4 — сводка
5 — для новичков
6 — инвентарь
0 — выход
> 
```

Каждая введённая строка обрезается по краям (` \t\r\n`). `0` — выход. Неизвестная команда → `Неизвестный пункт меню: «<ввод>»`.

**Ошибки.** `std::invalid_argument` из любой команды печатается как `Ошибка: <what>`, затем снова меню.

**EOF.** Конец ввода в любом месте, в том числе посреди вопроса, — `run()` молча возвращается, без `Ошибка` и без частичного результата. Последняя строка без `\n` обрабатывается.

**Вопросы.** `Вид (id): `, `Кличка: `, `Простота (1–10): ` (с длинным тире), `Износ, %: `, `Расход, кВт·ч/сут: `.

**Разбор чисел.** Простота — целое, вся строка должна разобраться: `5.5`, `7abc`, `абв` → `Ожидалось целое число: «<ввод>»`. Износ и расход — `stod`: `1e1` допустимо, мусор → `Ожидалось число: «<ввод>»`; `nan` разбирается и отклоняется конструктором («Износ не может быть NaN»).

| Пункт | Поведение и вывод |
|---|---|
| 1 | Строка на вид: `id`, затем название; у `needEnergy` — ещё `нужен расход энергии`. Ширина колонки `id` — максимум из 12 и (самый длинный `id` + 1), колонки названия — из 20 и (самое длинное + 1). У неэлектрических видов после названия пробелов нет. |
| 2 | `Вид (id): `. Неизвестный → `Ошибка: Неизвестный вид транспорта: <id>` сразу, без остальных вопросов. Далее кличка, простота, износ и, если `needEnergy`, расход. Итог: `Принят: ВК-000001 Самокат «Молния»` или `Отклонён: <reason>`. |
| 3 | Список видов вещей в формате пункта 1, `Вид (id): `, расход — только для `needEnergy`. Неизвестный → `Ошибка: Неизвестный вид вещи: <id>`. Итог: `Поставлен на баланс: ВК-000002 Шлем`. |
| 4 | `Транспорт: N, вещей: M, суточный расход: X кВт·ч.` — X с точностью до сотых без хвостовых нулей: `5.8`, `5.25`, `0`. |
| 5 | Строки `padRight(номер, 12) + padRight(имя, 32) + "простота N"`. Пусто → `Подходящего транспорта нет.` |
| 6 | Строки `padRight(номер, 12) + padRight(имя, 32) + "транспорт" / "вещь"`. Пусто → `Инвентарь пуст.` |

| ID | Сценарий (ввод) | Ожидание |
|---|---|---|
| AP-01 | `0` | меню выведено один раз, выход |

## 11. Поведение вне контракта — не тестировать

Эти случаи не определены требованиями; тест на них закрепил бы случайную реализацию.

- `formatInventoryNumber` для 0 и отрицательных: `Fleet` такие номера не выдаёт.
- Пользовательский creator, возвращающий `nullptr`: фабрика возвращает его как есть.
- `registerType` с пустым `title`: сейчас допускается.
- Расход `-0.0`: проходит проверку `< 0`.
- `FleetReports::inventory()` для объекта без номера: через `Fleet` недостижимо (было бы `std::bad_optional_access`).
- Переполнение `lastNumber_` после `INT_MAX` добавлений.
